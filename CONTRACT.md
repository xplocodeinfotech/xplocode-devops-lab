# Shared API contract — frontend baseline

There was no existing contract or application in this repository. These are the
React frontend's initial expectations, not a claim that a backend exists. Confirm
this baseline before implementing the first backend. OpenAPI is in
`api-contract/openapi.yaml`.

The runtime `apiBaseUrl` may contain a cloud function prefix. Append the full
`/api/...` path to that prefix; do not discard it. Example:
`https://example.com/function/student-app` + `/api/students`.

| Method | Path | Success response |
| --- | --- | --- |
| POST | `/api/auth/login` | 200: `{ "token": "<JWT>", "expiresIn": 3600, "user": { "username": "learner" } }` |
| GET | `/api/students` | 200: array of student objects |
| GET | `/api/students/{id}` | 200: student object |
| POST | `/api/students` | 201: created student object |
| PUT | `/api/students/{id}` | 200: updated student object |
| DELETE | `/api/students/{id}` | 204: no body |
| GET | `/api/health` | 200: `{ "status": "ok" }` |

Login body: `{ "username": "learner", "password": "<user input>" }`.
No demo account or backend password has been provisioned yet.

Student: `{ "id": 1, "name": "Arun", "email": "arun@example.com", "year": 3 }`.
Create/update body contains the same fields except `id`. IDs are positive integers,
generated by the server. Names are trimmed, nonblank strings up
to 100 characters. Email is a valid address up to 254 characters, stored and returned in
lower case, and unique. Initial workshop year choices are integers 1–4.

All student endpoints require `Authorization: Bearer <JWT>`. Errors use
`{ "error": { "code": "VALIDATION_ERROR", "message": "Readable explanation" } }`.
Use 400 for validation, 401 for missing/invalid/expired credentials, 404 for a
missing student, 409 for duplicate email, and 500 for unexpected server errors.
Backend validation remains mandatory regardless of frontend validation.

The frontend keeps the token only in memory. Refresh requires signing in again;
logout clears it. A protected request returning 401 returns the user to login.
Mutation requests are not retried automatically. A network failure may occur
after a mutation commits: refresh the list before repeating that operation.

Browsers call the API cross-origin, so every backend must answer CORS preflight for a configured
allowlist of origins (never `*`) and allow the `Authorization` and `Content-Type` headers.

Demo mode bypasses real authentication (any non-blank username and password) and simulates the student service in
memory. Its records are sample data, not backend or database verification.
